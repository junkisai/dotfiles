# ブランチ名

ブランチを `<種類>/<内容>` の形で名付け、まだ push していない作業ブランチを規則に合わせる。

## 規則

- 種類: `feature`（新機能）、`fix`（不具合修正）、`hotfix`（本番の緊急修正）、`refactor`（リファクタリング）、`docs`（文書）、`style`（コードスタイル・見た目）、`chore`（その他の調整・環境設定）
- 内容: 動詞から始まる英語のケバブケース（`add-`、`update-`、`remove-`、`fix-` など）。短くても意味が伝わるようにする。
- 例: `feature/add-contact-form`、`fix/delete-confirm`、`docs/update-readme`、`chore/move-agents-md-to-root`

## 手順

- 種類と内容は、ベースからの変更と未コミットの差分から決める。差分がまだ無ければ依頼の内容から決める。
- 新しく作るブランチは、この規則で名付ける。
- 今のブランチが規則に合わず、まだ push していなければ（upstream が無く、リモートに同名のブランチも無い）、`git branch -m <新しい名前>` で付け直す。Orca が worktree に付ける仮の名前（`coffinfish` のような生き物の名前）もこれに当たる。
- 同名のブランチがあれば内容を変えて重複を避ける。
- 規則に合っている名前、push 済みのブランチ、ベースブランチ（`main`、`staging` など）は変えない。push 済みのブランチを変えるよう頼まれたら、リモートの古いブランチと PR をどう扱うかを確かめてから進める。

完了は `git branch --show-current` で名前を確認した時点。付け直した場合は旧名と新名を、変えなかった場合はその理由を伝える。
