# ブラウザでの動作確認

変更に影響する「操作 → 画面で確認できる結果」を短いチェックリストにして観測する。内部実装だけで表示や操作の成功を判断しない。

## モード

- 対象 URL が指定されていればそれを使う。ローカル変更の確認は local、デプロイ済みの確認は staging と推定し、区別が結果や権限に影響する場合だけ聞く。
- 接続を用意するときは [ブラウザ接続](references/browser-connection.md) を参照する。実行環境で指定されたブラウザツールを優先する。
- 録画が依頼された場合だけ [録画手順](references/recording.md) を読む。出力先の既定は `~/Downloads/browser-check/<日付-対象>/`。
- before / after の比較は同じ観測条件を使う。切り替え方法が既存設定や履歴から分かれば用意し、不明なら必要な情報を聞く。ユーザーの作業を破棄して切り替えない。

## 完了条件

対象の操作と関連する空・読み込み・エラー等の状態を、影響に応じて確認する。修正まで依頼されている場合は見つかった問題を直し、失敗した観測を再確認する。確認だけの依頼では結果を報告する。

観測結果、未確認事項、証跡の場所を伝える。PR 投稿が依頼に含まれる場合はその結果まで残す。録画権限がない場合は録画不能を伝え、実施できる確認は進める。動画の代わりに静止画で完了したと扱わない。
