# コミット

依頼された変更を、絵文字付きの日本語メッセージで新しいコミットにする。

- `git status` と差分で対象を確認する。既存のステージ範囲を尊重し、追加する場合は関連ファイルを個別指定する。機密情報や無関係な変更を含めない。
- コミットの前にブランチ名を確認し、下の「ブランチ名」の規則に合わせる。
- `git diff --cached` で実際に入る内容を確認し、変更の目的が伝わる要約を書く。例: `🐛 保存失敗時に入力が消える問題を修正`。機能は ✨、整理は ♻️、文書は 📝、設定は 🔧 を目安にする。
- フックを有効にしたままコミットし、今回の変更が原因の失敗を直して再実行する。検証済みのチェックを理由なく繰り返さない。
- 複数行のメッセージは一時ファイルに書いて `git commit -F <file>` へ渡す。
- amend と push は依頼に含まれる場合だけ行う。ステージだけの依頼からコミットへ広げない。

完了はコミットの作成を `git log -1` と状態で確認した時点。ハッシュ、要約、残した変更があればその範囲を伝える。ブランチ名を付け直した場合は旧名と新名も伝える。

## ブランチ名

ブランチは `<種類>/<内容>` の形で名付ける。

- 種類: `feature`（新機能）、`fix`（不具合修正）、`hotfix`（本番の緊急修正）、`refactor`（リファクタリング）、`docs`（文書）、`style`（コードスタイル・見た目）、`chore`（その他の調整・環境設定）
- 内容: 動詞から始まる英語のケバブケース（`add-`、`update-`、`remove-`、`fix-` など）。短くても意味が伝わるようにする。
- 例: `feature/add-contact-form`、`fix/delete-confirm`、`docs/update-readme`、`chore/move-agents-md-to-root`

作業ブランチが規則に合わず、まだ push していなければ（upstream が無く、リモートに同名のブランチも無い）、ベースからの変更と今回の差分に合う名前へ `git branch -m <新しい名前>` で付け直す。Orca が worktree に付ける仮の名前（`coffinfish` のような生き物の名前）もこれに当たる。同名のブランチがあれば内容を変えて重複を避ける。

規則に合っている名前、push 済みのブランチ、ベースブランチ（`main`、`staging` など）は変えない。

## skill-guard を使う環境

`~/.claude/hooks/skill-flag-path.sh` が存在し、skill-guard が有効な場合は、操作を行うセッションでスクリプトを実行し、返されたフラグパスを次の `touch` に渡す。親と子のセッションでフラグは共有されない。フックの回避や無効化はしない。

```bash
bash "$HOME/.claude/hooks/skill-flag-path.sh"
# 出力されたパスを確認して、別コマンドで touch に渡す
```

実行権限は現在の環境の制約に従う。書き込み先や通信が制限されている場合に必要な権限を使い、すべての環境へ権限昇格を固定しない。
