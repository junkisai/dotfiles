# コミット

依頼された変更を、絵文字付きの日本語メッセージで新しいコミットにする。

- `git status` と差分で対象を確認する。既存のステージ範囲を尊重し、追加する場合は関連ファイルを個別指定する。機密情報や無関係な変更を含めない。
- `git diff --cached` で実際に入る内容を確認し、変更の目的が伝わる要約を書く。例: `🐛 保存失敗時に入力が消える問題を修正`。機能は ✨、整理は ♻️、文書は 📝、設定は 🔧 を目安にする。
- フックを有効にしたままコミットし、今回の変更が原因の失敗を直して再実行する。検証済みのチェックを理由なく繰り返さない。
- 複数行のメッセージは一時ファイルに書いて `git commit -F <file>` へ渡す。
- amend と push は依頼に含まれる場合だけ行う。ステージだけの依頼からコミットへ広げない。

完了はコミットの作成を `git log -1` と状態で確認した時点。ハッシュ、要約、残した変更があればその範囲を伝える。

## skill-guard を使う環境

`~/.claude/hooks/skill-flag-path.sh` が存在し、skill-guard が有効な場合は、操作を行うセッションでスクリプトを実行し、返されたフラグパスを次の `touch` に渡す。親と子のセッションでフラグは共有されない。フックの回避や無効化はしない。

```bash
bash "$HOME/.claude/hooks/skill-flag-path.sh"
# 出力されたパスを確認して、別コマンドで touch に渡す
```

実行権限は現在の環境の制約に従う。書き込み先や通信が制限されている場合に必要な権限を使い、すべての環境へ権限昇格を固定しない。
