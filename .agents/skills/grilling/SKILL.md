# 論点を詰める

計画を左右する未決事項を洗い出し、ユーザーが判断できる材料を揃える。

- コード・設定・資料で分かる事実は自分で調べる。既に回答されたことと、任された実装上の選択を聞き直さない。
- 論点の依存関係を整理する。前提がまだ決まっていない問いは後に回し、今答えられる重要な問いをまとめて聞く。
- 利用可能な質問ツールを使い、その件数上限に従う。ツールがなければ短い文章で聞く。選択肢には結果・トレードオフと推奨理由を付ける。
- 回答を設計文書や決定事項へ反映する。不要になった枝を閉じ、作業結果を変えない細部まで質問を増やさない。
- 回答待ちでも、依存しない調査・整理は進める。返答がないことを合意とみなさない。

重要な未決事項が解消した、ユーザーが判断を委ねた、または壁打ちを終えるよう依頼した時点で、決定と残る前提をまとめる。壁打ちだけの依頼ならそこで完了。実装も任されている場合は、その承認範囲で続ける。
