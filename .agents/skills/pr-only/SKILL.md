# PR 作成

コミット済みの差分から、日本語のタイトルと本文を持つ GitHub PR を作る。

1. 対象リポジトリ・現在のブランチ・既存 PR・未コミット変更を確認する。未コミット変更があっても、依頼対象が既存コミットならその範囲で進める。依頼された変更自体が未コミットなら、コミットまで任されている場合は `pr` へつなぐ。単なる手順の質問には説明で答える。
2. ベースは指定を優先し、なければリモートのデフォルトブランチを確認する。通信失敗を `main` という推測に置き換えない。
3. ベースとの差分とコミット履歴を読み、問題・変更後の振る舞い・確認結果を説明する。リポジトリの PR テンプレートを優先し、背景や画像は役立つ場合に付ける。読めなかった範囲は推測せず、確認範囲を報告する。
4. PR 作成の依頼に必要な通常の push は、その依頼の範囲で実行する。リモート・ブランチを確認し、force push は行わない。既存リモートブランチにも未送信コミットがあれば送る。まだ push していないブランチは、`branch-name` スキルで規則に合わせてから push する。
5. 本文を一時ファイルに書いて `gh pr create --title <title> --body-file <file> --base <base> --head <branch>` へ渡す。作成失敗時は既存 PR を確認してから再試行し、重複を作らない。

既定は `--draft --assignee "@me"`。ユーザーの draft・担当者指定を優先する。担当者の設定だけが失敗した場合は PR の作成状態を先に確認し、担当者を設定できなかった旨を報告する。

完了は対象ブランチの PR URL と状態を確認した時点。URL と未反映の変更があれば伝える。レビューコメント投稿・監視・ready 化は、その作業まで依頼された場合に進める。

## skill-guard を使う環境

`~/.claude/hooks/skill-flag-path.sh` が存在し、skill-guard が有効な場合は、操作を行うセッションでスクリプトを実行し、返されたフラグパスを次の `touch` に渡す。親と子のセッションでフラグは共有されない。フックの回避や無効化はしない。

```bash
bash "$HOME/.claude/hooks/skill-flag-path.sh"
# 出力されたパスを確認して、別コマンドで touch に渡す
```

実行権限は現在の環境の制約に従う。書き込み先や通信が制限されている場合に必要な権限を使い、すべての環境へ権限昇格を固定しない。
