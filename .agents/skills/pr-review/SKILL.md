# PR 上でのレビュー対応

対象 PR と依頼内容に応じて、必要な操作を選ぶ。一般的なコードレビューやローカル差分の説明から、PR 作成・投稿へ自動で広げない。

- 実装意図の投稿: [投稿形式と行の照合](references/posting.md) を読む。差分から明らかな説明を増やさず、判断理由を必要な箇所に付ける。
- レビュー反映・返信: [取得と対応記録](references/responding.md) を読む。未処理を取得し、依頼範囲で修正・検証・コミット・push・返信を進める。仕様変更の判断は既存の合意から確認する。
- 新規 PR が必要で、その作成まで依頼されている場合だけ `pr` を使う。既存 PR があれば再作成しない。
- draft を外すのは、ユーザーから ready 化の承認を得ている場合に限る。既に承認された内容を聞き直さない。

指定された投稿・指摘対応が完了し、PR URL、反映状況、未解決事項を報告して完了する。継続監視は依頼された場合に実施する。
