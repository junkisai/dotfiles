# 変更から PR まで

依頼された変更のコミット、通常の push、PR 作成を完了する。途中の段階を既に終えていれば続きから進める。

- 差分と既存 PR を確認し、依頼対象を特定する。ステージ済みの範囲と他の作業を保護する。
- ファイル変更はリポジトリの worktree 規約に従う。既存の worktree の作業ブランチを利用し、別のブランチへ移らない。名前の付け直しは `branch-name` スキルに従う。`.Codex/worktrees/` も対象であり、`main` 以外という理由だけでは断らない。
- メインの作業ディレクトリにある未コミット変更を扱う場合は、`branch-name` スキルで名付けたブランチの専用 worktree を作り、対象の差分・新規ファイルだけを安全に移す。元の変更は破棄せず、移した差分を照合する。detached HEAD やベースブランチそのものを push する状態は先に解消する。
- コミットが必要なときだけ `commit` を使う。作業ブランチの差分コミットが既にあれば、未コミット変更がなくても PR 作成へ進む。
- `pr-only` を使って push と PR 作成を行う。対象に差分コミットも未コミット変更もなければ、その事実を伝えて終了する。

完了時はブランチ、コミット、PR URL を報告する。PR 作成だけの依頼にレビュー投稿や無期限の監視を追加しない。失敗時は完了した段階と未完了の理由を示す。
