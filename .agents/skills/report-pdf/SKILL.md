# 社外向けの報告資料 PDF

冒頭で結論が分かり、数字を表と図で確かめられる A4 縦の報告書を作る。HTML と印刷用の CSS で組み、図は SVG で描き、Chrome で PDF にする。Claude Docs や Artifact の書き出しは使わない。Web ページの見た目のまま社外に出てしまうため。

## 組み立て

- 中身を先に固める。章ごとに結論の一文を決め、比べる項目が多いものは表、大小・増え方・内訳は図にする。結論の数字は、冒頭の要約に 4 つまでのカードで並べる。
- [ひな形](assets/template.html) をコピーして書き始める。表紙、要約のカード、表、図、提案の囲み、※の注記、式の囲み、塗り分けた早見表がそろっている。
- 色はひな形の `:root` のパレットだけを使う。部品は役割の色（`--text`・`--emphasis-text` など）を、図はクラス（`c-hl`・`c-muted` など）を使い、色を直書きしない。目立たせる色は主色（primary）の 1 系統にし、注記の※だけ `--caution-text` にする。
- 図は [図の描き方](references/charts.md) に従って描く。
- 章は `h2.pb` で改ページし、表や図がページをまたがないようにする。書名とページ番号は `@page` で出すので、`@top-right` の書名を資料の題に合わせる。

## 文章

- です・ます調で書く。社内の作業メモ（確認事項のチェックリスト、メンション、関数名・ファイルパス・内部の ID）は入れない。
- 実測と推定を分け、前提（規模・為替・単価を確かめた日）を表にする。外から取った単価や仕様は、出典の URL と確かめた日を末尾に載せる。
- 同じ数字が要約・本文・表・例に何度も出る。1 つを直したら HTML の中を検索し、合計や例の計算も含めて全部をそろえる。

## PDF にして確かめる

```sh
bash <skill>/scripts/build.sh <資料>.html [<出力>.pdf]
```

- 出力の既定は、HTML と同じ場所・同じ名前の `.pdf`。ページ数と、全ページを PNG にしたフォルダを出す。Google Chrome と poppler（`pdfinfo`・`pdftoppm`）が要る。
- 全ページの画像を実際に見て、次があれば直して作り直す。
  - 見出しやリード文だけがページ末に残る、1〜2 行だけが次のページに送られる、表や図がページをまたぐ
  - 要約のカードの数字が折り返す
  - 図の数字が棒や隣の数字に触れる（図のあるページは拡大して見る）

## 渡すとき

PDF と元の HTML を同じ名前で並べて置く（例：`<題>_<YYYYMMDD>.pdf` と `.html`）。置き場所の指定が無ければ `~/Downloads/` にする。直すときは HTML を直して作り直す。

報告では、PDF のパスとページ数、確かめたこと、推定のまま残っている数字を伝える。
