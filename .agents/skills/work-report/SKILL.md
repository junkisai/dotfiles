# 作業報告

PR の本文と活動履歴から、利用者に何ができるようになったかを短く報告する。

- 日付・タイムゾーン・リポジトリ・対象者を決める。指定済みなら確認を繰り返さない。現在の checkout を使える文脈ならその範囲を明示して進め、複数候補がある場合だけ聞く。
- `gh pr list --repo <owner/repo> --state all --author <user> --limit 100 --json number,title,state,createdAt,mergedAt,updatedAt,url,body,isDraft` 等でデータを得る。100件で期間をカバーできなければ追加取得する。担当者指定なら author ではなく assignee を使う。
- 作成日・マージ日・更新日を区別し、依頼に合う活動を期間内で抽出する。updatedAt だけでは何の作業があったか分からないため、必要ならコミットやレビューの日時も確認する。
- PR タイトルだけでなく本文を読み、機能や目的ごとにまとめる。未完了の設計や draft を実装完了と表現しない。取得できた範囲だけを使う。
- 絞り込み済み GitHub リンクを挨拶の下に置き、数項目の箇条書きでまとめる。リンクの created / merged / updated の条件を実際の抽出と合わせる。
- 次の予定は指定があれば使う。根拠がなければ創作せず省くか、未定とする。

既定の文体は「今日の作業内容の共有です！」に続く簡潔な日本語。過去日なら日付を明記する。完成した報告文を返し、メールやチャットへの送信は送信まで依頼された場合に行う。
